## 보도자료 (1쪽)

**브라우저 탭 하나로, 바이낸스 선물 모든 종목의 시세를 목록에서 골라 1분봉부터 일봉까지 실시간으로 본다**
계정도 키도 필요 없다 — 열면 종목 목록의 가격이 움직이고, 하나를 누르면 캔들과 거래량이 바로 뜬다. 선이 끊기면 끊겼다고 알려 준다.

- **누구를 위해**: 바이낸스 무기한 선물 가격을 지켜보며 차트 읽는 법을 익히려는 개인 (주문은 다른 곳에서 한다). 여러 종목을 오가며 보고 싶은 사람.
- **어떤 문제**: 종목을 바꿔 가며 분·시간 차트를 보려면 거래소 앱에 로그인하거나, 광고와 기능 제한이 있는 차트 사이트를 열어야 한다. 보고 싶은 건 가격뿐인데 화면이 무겁다.
- **해결**: 열면 현재 거래 중인 모든 선물 종목이 현재가와 24시간 등락률과 함께 나열되고 실시간으로 바뀐다. 목록에서 고르거나 기호·이름 일부를 입력해 찾아 열면 최근 500개 봉이 그려진다. 1분·5분·15분·1시간·4시간·1일 버튼으로 간격을 바꾸고, 종목을 바꿔도 같은 간격이 유지된다. 인터넷이 끊기면 "재연결 중"이 뜨고, 돌아오면 빠진 봉을 채운다. 거래가 끝난 종목은 목록에서 빠지고, 보고 있던 종목이 끝나면 이유를 알려 준다.
- **왜 지금 것보다 확실히 나은가**: 솔직히 **화면 기능으로는 TradingView·바이낸스 앱을 못 이긴다** (아래 비교표). 나은 점은 세 가지뿐이다. (1) 로그인·광고·기능 제한 없이 선물 종목 목록과 차트만 한 화면에 (TradingView 무료 요금제 제한은 2차 자료만 있고 현재 수치 확인 못 함), (2) 주문 기능이 아예 없어 실수로 주문할 일이 없다, (3) 내 PC 안에서 돌아 내 마음대로 고칠 수 있고 만드는 과정 자체가 학습이 된다. 사용자 목적이 학습이므로 (3)이 핵심 가치다.
- **사용자 한마디**: "코인 이름 일부만 치면 바로 5분봉이 떠서 좋아요." (가상)
- **시작하는 법**: 페이지를 연다 → 목록이 뜬다 (처음 선택은 BTCUSDT, 1분봉) → 목록에서 종목을 누르거나 검색창에 입력해 연다 → 위쪽 간격 버튼(1m 5m 15m 1h 4h 1d)으로 바꾼다.

## FAQ

### 사용자 질문
| 질문 | 답 |
|---|---|
| 주문도 되나요? | 아니요. 시세 조회 전용이다. 주문·잔고·API 키 입력 칸 자체가 없다. |
| 어떤 종목이 나오나요? | 바이낸스 USDⓈ-M **무기한** 선물 중 지금 거래 중인 종목 전부. 종목 목록은 바이낸스가 알려 주는 것을 그대로 쓰며 우리가 미리 적어 두지 않는다. 분기물(만기 있는 선물)은 요청 범위 밖이라 뺀다 (열린 질문 아님, 요청 문장 기준). |
| 종목 이름이 왜 `1000PEPEUSDT` 같나요? | 가격이 아주 낮은 코인은 바이낸스가 1000개 단위로 거래하게 만든다. 그래서 기호가 종목마다 다를 수 있고, 화면은 바이낸스가 준 기호를 그대로 보여 준다. 검색할 때 `PEPE` 만 쳐도 나와야 한다 (AC14). |
| 이동평균선 같은 지표는요? | 뺀다. 필요하면 2차. |
| 한국에서 열리나요? | **확인 전에는 장담 못 한다.** 바이낸스 공개 시세 주소가 지역·회사 서버 주소에 따라 451 오류로 막히는 사례가 있다. 만들기 전 첫 확인으로 내 PC 브라우저에서 열리는지 본다 (열린 질문 0번). |
| 값이 바이낸스 앱과 다르면요? | 같은 바이낸스 선물 시세를 쓰므로 같아야 한다. 다르면 오류로 본다 (AC8). |
| 연결이 끊기면요? | 상단에 "재연결 중"이 뜨고 자동으로 다시 붙는다. 목록은 다시 받아 맞추고, 보던 종목의 끊긴 동안 봉은 채운다 (AC6, AC7). |
| 보던 종목이 거래 종료되면요? | 화면에 "이 종목은 거래가 종료/정지되었습니다"가 뜨고 마지막 봉은 남기되 실시간 갱신은 멈춘다 (AC18). |
| 시간 표시는 어느 나라 기준인가요? | 한국 시간(KST)으로 고정 (사용자 결정 유지). |

### 내부 질문 (만들기 어려운가, 위험은, 가치는)

| 질문 | 답 |
|---|---|
| 가장 어려운 부분은? | (1) **451 차단**: 막히면 기능 자체가 없다. 클라우드 서버 중계는 서버 IP 가 막힐 가능성이 더 높다는 보고가 있다 ([Vercel 커뮤니티](https://community.vercel.com/t/binance-api-calls-on-vercel/29895), [바이낸스 개발자 포럼](https://dev.binance.vision/t/error-451-when-accessing-the-futures-api-from-us/16725)). (2) **끊김 후 복구**: 연결은 약 24시간마다 끊기도록 되어 있고 ([공식 문서](https://developers.binance.com/docs/derivatives/usds-margined-futures/websocket-market-streams)) 와이파이·절전으로도 끊긴다. 목록 스트림과 차트 스트림 둘 다 복구해야 한다. (3) **종목 전환 시 연결 정리**: 이전 종목 구독을 끊지 않으면 이전 종목 봉이 새 종목 차트에 섞인다 (AC16). (4) 마지막 봉 중복·누락 방지. |
| 새 범위에서 추가된 위험은? | 아래 "위험 목록" 표. |
| 하지 않을 것(범위 밖)은? | 주문, 잔고·포지션, 로그인, API 키 입력·저장, 보조지표, 그림 도구, 알림, 호가창·체결 내역, 스팟 시세, 만기 있는 분기물·코인마진(COIN-M) 선물, 즐겨찾기·저장(1차), 여러 종목 동시 차트(한 번에 한 종목만), 모바일 앱·모바일 화면 (웹 PC 기준 유지). |
| 실패하면 무엇이 망가지나? | 직접 금전 피해는 없다. 다만 **잘못된 가격을 맞는 것처럼 보여 주면** 그걸 보고 다른 곳에서 내리는 판단이 틀어진다. 종목이 바뀐 직후 이전 종목 가격이 남아 보이는 것이 새 범위의 대표적 위험이다. 그래서 "끊김", "마지막 갱신 시각", "거래 종료"를 숨기지 않는다 (AC6, AC7, AC15, AC18). |
| 비용은? | 공개 시세는 키·요금이 없다. 서버 없이 내 PC에서 열면 호스팅 비용 0. 대신 목록 실시간 스트림의 데이터량(아래 위험)과 주소·응답 형식 변경 시 유지보수가 든다. |
| 지표는? | **제외** (유지). 간격은 **1m, 5m, 15m, 1h, 4h, 1d** (유지). |

#### 사용하는 바이낸스 공개 시세 (기능 이름만, 설계는 다음 단계)

| 용도 | 주소 | 확인 상태 |
|---|---|---|
| 전체 종목 목록·상태 | `GET https://fapi.binance.com/fapi/v1/exchangeInfo` | 요청자 제공. 응답에 종목 기호·계약 종류·상태 필드가 있다는 것은 바이낸스 변경 내역에서 확인. 상태 값의 정확한 글자(예: 거래 중)와 무기한 구분 값은 **공식 문서 접속 오류로 이번에 확인 못 함** |
| 전 종목 24시간 시세 한 번에 | `GET https://fapi.binance.com/fapi/v1/ticker/24hr` | 요청자 제공. 요청 가중치 수치는 확인 못 함 |
| 목록 실시간 갱신 | `wss://fstream.binance.com/ws/!ticker@arr` | 요청자 제공. 검색에서 이 스트림의 현재 사양(갱신 주기, 폐지 여부)은 **확인 못 함** — 설계 전 공식 문서로 확인 |
| 선택 종목 캔들 | `GET /fapi/v1/klines?symbol=<기호>&interval=<간격>` + `wss://fstream.binance.com/ws/<기호소문자>@kline_<간격>` | 요청자 제공 (기존 BTCUSDT 기획에서 쓰던 방식과 동일) |

규칙: 종목 목록은 위 목록 주소에서 받아 쓰고 **코드에 종목명을 박지 않는다.** 새 종목이 상장되거나 기호가 바뀌어도 화면이 따라가야 한다.

#### 위험 목록 (새 범위)

| 위험 | 내용 | 줄이는 첫 수 |
|---|---|---|
| 목록 스트림 데이터량 | 전 종목 시세 스트림 1개가 수백 종목의 값을 계속 보낸다. 화면이 느려지거나 PC·회선 부담이 될 수 있다. 실제 초당 데이터량은 확인 못 함 | 만들기 전 브라우저로 1분간 받아 크기·갱신 주기를 측정 (열린 질문 아님, 설계 전 확인 항목). 느리면 목록 갱신 주기를 제한 |
| 목록 성능 | 종목이 수백 개라 모두 그리면 스크롤·검색 입력이 버벅일 수 있다 | AC20 으로 기준을 못 박고, 보이는 줄만 그리는 방식 등은 설계 담당이 선택 |
| 요청 제한(IP 가중치) | 바이낸스는 IP 당 분당 요청 가중치 한도가 있다. 공식 변경 내역에 선물 일반 한도 분당 2400 이라는 기록이 있으나 ([바이낸스 문서](https://binance-docs.github.io/apidocs/futures/en)) 현재 값과 각 요청의 무게는 확인 못 함. 전 종목 24시간 시세는 종목 지정 없이 부르면 무겁다고 알려져 있으나 수치 미확인. 초과 시 429 오류, 계속 어기면 IP 일시 차단 | 목록 REST 는 열 때와 재연결 때만 부른다 (종목 바꿀 때마다 부르지 않는다). 종목 전환 시 부르는 것은 캔들 1회뿐. 429/418 이 오면 화면에 이유와 대기 시간 표시 (AC21) |
| 상장폐지·정지 종목 | 목록에 있던 종목이 거래 종료·정지될 수 있다. 상태 값의 정확한 종류는 확인 못 함 | 거래 중이 아닌 종목은 목록에서 빼고, 보던 종목이면 안내 (AC18) |
| 종목 전환 시 연결 누수 | 이전 구독을 안 끊으면 연결이 쌓이고 이전 종목 봉이 섞인다. 바이낸스는 연결당 스트림 수 한도가 있고 공식 문서 간 수치가 달랐음(200/1024) | AC16 으로 "동시 차트 연결은 1개" 시험 |
| 기호 표기 차이 | `1000PEPEUSDT` 등 1000배 단위 종목은 이름 검색이 어긋나고, 가격이 우리가 아는 코인 가격의 1000배로 보일 수 있다 | 기호를 그대로 보여 주고 검색은 이름 일부로도 되게 (AC14). 화면에 "1000배 단위" 안내를 넣을지는 열린 질문 |
| 451 차단 | 기존과 동일 | 코드 전 브라우저 확인 (열린 질문 0번) |

## 판단 (만들 가치가 있나)

| 기준 | 답 | 근거 |
|---|---|---|
| 1. 대상 사용자가 구체적인가 | **예 (조건부)** | 요청자 본인, 학습 목적, 여러 종목을 오가며 보는 개인. 얼마나 자주 쓰나는 여전히 열린 질문 5번. |
| 2. 기존 대안보다 **확실히** 나은 점이 보이는가 | **아니오 (기능 면)** | TradingView·바이낸스 화면이 종목 목록·검색까지 이미 갖췄고 기능 면에서 앞선다. 이 화면의 우위(단순함, 주문 없음, 통제권)는 취향이다. |
| 3. 완료 조건이 관찰 가능한가 | **예** | AC1~AC22. |
| 4. 가장 큰 위험과 첫 수가 있는가 | **예** | 451 차단과 전 종목 스트림 데이터량. 첫 수: 코드 전 브라우저로 목록·klines 주소가 열리는지, 전 종목 스트림이 1분간 얼마나 받아지는지 측정. |

**판단: 조건부 만들기 권고 (학습 목적 전제).** 기준 2가 기능 면에서 "아니오"지만, 사용자가 목적을 **학습**으로 밝혔고 이전 기획서가 정한 "학습이면 만들 만하다" 조건에 해당한다. 범위가 BTCUSDT 하나에서 전 종목으로 커진 만큼 작업량은 기존보다 확실히 늘었다 (목록 실시간 스트림, 검색, 종목 전환 연결 관리, 상장폐지 처리). 학습 효과는 커지지만 "그냥 가격만 보기"가 목적이었다면 보류가 맞다는 점은 그대로다. **첫 수는 같다**: 451 여부와 스트림 데이터량 확인.

## 이번 조사에서 확인하지 못한 것
- 바이낸스 공식 개발자 문서 접속이 이번에 오류(연결 끊김)로 실패해, 종목 정보 응답의 상태 값 글자·무기한 구분 값, 24시간 시세 요청의 가중치, 전 종목 스트림(`!ticker@arr`)의 현재 사양·갱신 주기·데이터량은 직접 확인하지 못했다. 설계 전 확인 필요.
- 선물 일반 한도 분당 2400 은 바이낸스 변경 내역에서 본 값이며 현재도 같은지 재확인 필요.
- TradingView 무료 요금제의 현재 정확한 제한 수치 (2차 자료만).
- WebSocket 한 연결당 스트림 수 한도 (공식 문서 간 200/1024 불일치). 이제 연결은 목록 1 + 차트 1 이라 영향은 낮음.
- 한국에서의 451 발생 여부 (열린 질문 0번).
- Lightweight Charts 최신 버전과 거래량 표시 방식.
- 승인 표시는 하지 않았다 (사용자 승인 후 지휘자가 적는다).
